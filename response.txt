Here's the runbook. Run it on the server as the admin user (`ryan`), repo at `~/server-setup`. Nothing here needs a code change from me.

## A. Confirm the cause (read-only)

```bash
cd ~/server-setup
grep -n SNAPSHOT_RENAMES .env
ls -ld ~/www/spam-destroyer* 2>/dev/null
grep -E '^(APP_URL|SESSION_DOMAIN|ASSET_URL)=' ~/www/spam-destroyer.hellyer.kiwi/.env
sudo podman exec nginx nginx -T 2>/dev/null | grep -n 'spam-destroyer'
```

You should see the rename active, `.com` absent, and `APP_URL=https://spam-destroyer.hellyer.kiwi`.

## B. Stop the rename

Edit `.env` and clear the mapping (it's test-only, line 86):

```
SNAPSHOT_RENAMES=""
```

Commenting it out also works. Without this, every future `deploy.sh` re-provisions `.com` under the subdomain name again.

## C. Repoint spam-destroyer.com at itself

```bash
cd ~/server-setup
sudo bash scripts/provision-site.sh spam-destroyer.com --domain spam-destroyer.com
```

This creates `~/www/spam-destroyer.com`, rsyncs the files there, reimports the DB, sets `APP_URL=https://spam-destroyer.com`, clears Laravel config/cache, and reloads nginx. Verify:

```bash
grep -E '^APP_URL=' ~/www/spam-destroyer.com/.env     # -> https://spam-destroyer.com
curl -sI https://spam-destroyer.com | head -n1        # -> HTTP/2 200
curl -sI https://spamannihilator.com | head -n1       # -> 301 to spam-destroyer.com
```

## D. Remove the test domain entirely

The subdomain is referenced in four places:

| File | What to delete |
|---|---|
| `nginx/conf.d/php-site.conf` | lines with `spam-destroyer.hellyer.kiwi` in `$site_root` (24), `$site_access_log` (38), `server_name` (68), and the header comment (5) |
| `nginx/nginx.conf.template` | `spam-destroyer.hellyer.kiwi "laravel";` in the `$platform_type` map (91) |
| `certbot/domains.test.txt` | `spam-destroyer.hellyer.kiwi` (line 5) |

Safe, with backups:

```bash
cd ~/server-setup
cp nginx/conf.d/php-site.conf nginx/conf.d/php-site.conf.bak
cp nginx/nginx.conf.template nginx/nginx.conf.template.bak
cp certbot/domains.test.txt certbot/domains.test.txt.bak

sed -i '/spam-destroyer\.hellyer\.kiwi/d' nginx/conf.d/php-site.conf
sed -i '/spam-destroyer\.hellyer\.kiwi/d' nginx/nginx.conf.template
sed -i '/spam-destroyer\.hellyer\.kiwi/d' certbot/domains.test.txt
```

Then re-render and reload (this regenerates `nginx/nginx.conf` from the template):

```bash
sudo bash scripts/render-config.sh
sudo podman exec nginx nginx -t && sudo podman exec nginx nginx -s reload
```

Delete the leftover files, logs, and DNS record:

```bash
sudo rm -rf ~/www/spam-destroyer.hellyer.kiwi
sudo rm -rf ~/logs/spam-destroyer.hellyer.kiwi
```

Then remove the `spam-destroyer.hellyer.kiwi` A/AAAA record at your DNS provider. The production cert (`certbot/domains.txt`) never included it, so no cert change is needed; the test cert just drops it on its next renewal.

## Order matters

Do **B then C first** and confirm `.com` is healthy, then do **D**. Steps B/C alone fix `spam-destroyer.com`; D is the cleanup that makes the test domain cease to exist.

Two notes: `.env.example` and the docs (`README.md`, `PODMAN_PLAN.md`, script comments) still mention the subdomain in examples — cosmetic only, but worth tidying the next time you commit. And if you'd rather keep the subdomain serving the same app instead of deleting it, say so and skip D.
